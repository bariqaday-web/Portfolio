# Salix — واجهات الزبون

سوق إلكتروني (Next.js 15 App Router + TypeScript + Tailwind CSS)، بالعربية
وباتجاه RTL كامل.

## التشغيل

npm install
npm run dev

## تسجيل الدخول وتفعيل البريد

اضبط `NEXT_PUBLIC_SITE_URL` على أصل النطاق الثابت في الإنتاج، مثل `https://your-domain.example`؛ اتركه غير مضبوط محلياً لاستخدام أصل بيئة التطوير الحالية. أضف `${NEXT_PUBLIC_SITE_URL}/auth/callback` إلى Supabase Auth > URL Configuration > Redirect URLs، واضبط Site URL على نطاق الإنتاج.

في Google Cloud Console، يجب أن يكون Authorized redirect URI هو عنوان callback الخاص بمشروع Supabase (`https://<project-ref>.supabase.co/auth/v1/callback`)، وليس مسار التطبيق. أضف أصل التطبيق الثابت إلى Authorized JavaScript origins. لبيئة Codespaces استخدم نطاقاً موثوقاً مسموحاً في Supabase Redirect URLs؛ لا تثبّت رابط Codespace مؤقتاً في إعدادات الإنتاج.

تأكيد البريد يمر عبر `/auth/callback` لتبادل رمز PKCE وإنشاء جلسة التطبيق. لا تستخدم مفاتيح الخدمة في المتصفح، ولا تحفظ بيانات دخول حقيقية في ملفات `.example`.

## اختبارات الجاهزية

شغّل اختبارات المنطق باستخدام `npm test`. لاختبارات المتصفح على سطح المكتب والهاتف،
ثبّت Chromium مرة واحدة باستخدام `npx playwright install chromium` ثم شغّل
`npm run test:e2e`. تُدار بيانات حسابات الاختبار محلياً في `.env.test.local`
(يمكن نسخ أسماء المتغيرات من `.env.test.local.example`)؛ استخدم بيئة اختبار منفصلة
ولا تضع بيانات الدخول أو مفاتيح الإنتاج في Git.

## تطبيق تحديثات قاعدة البيانات

قبل نشر تغييرات الطلبات والمحادثات والإشعارات والتقييد، طبّق ملفات SQL الجديدة في
`supabase/migrations` على مشروع Supabase بالترتيب الزمني. تتطلب هذه التحديثات الجداول
الأساسية الحالية مثل `orders` و`conversations` و`posts` و`post_comments` و`stories`.
تتضمن ترحيلات الطلبات إعادة تحميل مخطط PostgREST لمعالجة أخطاء ذاكرة المخطط؛ إذا
بقي الخطأ بعد تطبيقها، أعد تحميل المخطط من لوحة Supabase.
لتحليلات المدن وساعات النشاط وتسجيل آخر ظهور للمستخدم، طبّق
`2026_10_04_usage_analytics.sql` ثم `2026_10_04_usage_quality.sql`.
تعتمد المدينة على قيمة المدينة التي أدخلها المستخدم في ملفه الشخصي، ويُسجّل
وقت النشاط من الخادم؛ لا تُستخدم إحداثيات GPS أو خدمة تحديد موقع عبر IP.
إذا ظهرت استجابة `403` من `orders`، طبّق أيضاً
`2026_10_03_orders_rls.sql` لإعادة ضبط صلاحيات قراءة الطلب وإدراجه للمستخدم المسجّل.
لمنع التاجر من طلب منتجات متجره أو فتح محادثة مع نفسه، طبّق
`2026_10_05_prevent_self_orders_and_chats.sql`؛ يمنع الترحيل السجلات الجديدة ذات الأطراف المتطابقة.
لجعل باقات الإعلانات مجانية خلال الإطلاق، طبّق
`2026_10_05_free_ad_launch.sql` بعد إعداد جداول الإعلانات.

ترحيل تقييد المحتوى يضيف قيوداً مستقلة لنشر المنشورات والقصص والتعليقات، ويُرسل
إشعاراً داخلياً عند تفعيل القيود أو رفعها. لا تنفّذ هذا الترحيل قبل وجود جدول
`public.notifications`؛ يعرّف الترحيل دالة `public.is_admin()` إذا لم تكن موجودة.
لتفعيل فتح الإعلان والتعليق المرتبط مباشرة من الإشعار، طبّق أيضاً
`2026_10_04_notification_destinations.sql` بعد ترحيلات الإشعارات السابقة.
لإظهار إشعارات التعليقات والمتابعات الجديدة، طبّق أيضاً
`2026_10_03_activity_notifications.sql`.
لعرض إجراءات الحساب فقط بدلاً من رسائل ومكالمات الدردشة، طبّق
`2026_10_09_action_only_notifications.sql`؛ تبقى الإشعارات القديمة في القاعدة لكنها
لا تظهر في القائمة أو العداد. ولإصلاح قراءة رقم واتساب المتجر من السلة، طبّق
`2026_10_09_merchant_whatsapp_public_view.sql`؛ تعرض الواجهة العامة الرقم للتجار فقط.
ولتمكين صفحة المتجر من عرض عدد المتابعين دون كشف سجلات المتابعة، طبّق
`2026_10_09_store_followers_count.sql`.
لإخفاء منتجات الحساب تلقائياً عند تحويله من تاجر إلى زبون، ومنع قراءتها عبر
قاعدة البيانات، طبّق `2026_10_09_03_merchant_deactivation_visibility.sql`.
عند إعادة الحساب إلى تاجر، يعيد الترحيل المنتجات التي أخفاها تغيير الدور فقط؛
ولا يعيد تفعيل المنتجات التي كانت متوقفة قبل ذلك.
لتفعيل دفع الإعلانات اليدوي بالدولار، شغّل في Supabase SQL Editor بالترتيب:
`2026_10_08_add_sponsored_story_ads.sql`، ثم
`2026_10_08_zz_campaign_review_visibility.sql`، ثم
`2026_10_09_01_manual_usd_campaign_payments.sql`. هذا الملف الأخير ينشئ آلية إرسال
الإيصال ودوال مراجعة الأدمن؛ وإذا ظهر خطأ فيه، أعد تشغيل ملف 01 المحدّث كاملًا.
أما `2026_10_09_02_no_campaign_payment_notifications.sql` فهو ترحيل متابعة اختياري
لمن شغّل نسخة سابقة من الدفع اليدوي، ويوقف إشعار الدفع داخل المنصة. لا يستبدل دالة
مراجعة الأدمن، ويُشغّل بعد ملف 01.
بعدها اضبط أسعار الباقات بالدولار وأدخل رقم البطاقة/الحساب المحلي و/أو IBAN من
لوحة الأدمن. يرسل التاجر صورة الإيصال ورقم العملية، ويظهر الإعلان في قائمة
«بانتظار المراجعة» لدى الأدمن دون إرسال إشعار دفع داخل المنصة؛ لا يؤكد النظام
وصول المال آليًا. يتحقق الأدمن
من حسابه البنكي، ثم يوافق أو يرفض. عند الرفض يسجل النظام أن الإعادة مطلوبة، ويستطيع
الأدمن تأكيدها بعد تنفيذ التحويل يدويًا. إشعار تطبيق البنك لا يصل إلى ساليكس تلقائيًا
من دون تكامل رسمي مع البنك أو مزود الدفع.

## مساعد المتجر في الدردشة

المساعد محلي قائم على كلمات وقواعد عربية محددة، ويعتمد على بيانات المتجر المسجلة.
فعّله من إعدادات المتجر، ثم طبّق
`supabase/migrations/2026_10_04_local_store_assistant.sql` لحفظ إعدادات التوصيل
والاسترجاع والخصومات الخاصة بكل متجر، و
`supabase/migrations/2026_10_04_zz_store_assistant_customization.sql` لحفظ ساعات
العمل والفروع والحسابات المخصصة لكل تاجر، ثم
`supabase/migrations/2026_10_04_zzz_assistant_single_store_rule.sql` لإنشاء قاعدة
رد مستقلة لكل متجر. ثم طبّق
`supabase/migrations/2026_10_08_assistant_rules_management.sql` لترحيل القواعد
القديمة إلى قائمة قابلة للإضافة والتعديل والإيقاف والحذف من لوحة المتجر. كل قاعدة
خاصة بمتجر واحد، وتتحقق صلاحيات قاعدة البيانات من ملكية التاجر لها. الأسعار
والمخزون والأوصاف والطلبات تُقرأ للمتجر المرتبط بالمحادثة فقط؛ ولا يستطيع مساعد
متجر استخدام مخزون متجر آخر. لا يستند المساعد إلى نموذج توليدي: يرد من القواعد
المعتمدة أو البيانات المسجلة، ويسأل للتوضيح عند عدم وجود تطابق بدلاً من اختراع
معلومة. تُضاف قواعد ترحيب وأسئلة تمهيدية وانزعاج أولية قابلة للتعديل من لوحة
الإدارة عبر ترحيل قواعد الردود العامة. لا يرسل المساعد رسالة تحويل عامة عند الخطأ
أو خارج ساعات العمل؛ يسجل الخطأ للمراجعة. يظل طلب الموظف الصريح سبباً للتحويل،
كما تحمل بعض الحالات التي تتطلب تحققاً من المتجر علامة متابعة داخلية. لا ينفّذ
المساعد إلغاءً أو تعديلاً للطلبات. يمكن وضع عدة صياغات للرد في القاعدة الواحدة بفصلها
بـ `|||`؛ يختار المساعد صياغة مختلفة عن آخر رد من المتجر في المحادثة. يمكن استخدام
متغيرات مثل `{{businessHours}}` و
`{{branchLocations}}` و`{{socialLinks}}` و`{{shippingInfo}}` و
`{{paymentOptions}}` و`{{returnPolicy}}` و`{{offerInfo}}` داخل الردود المخصصة.
تتضمن معلومات الخصومات وصف العرض وكوده اللذين يضيفهما التاجر، أسعار المنتجات
المخفضة، وعناوين الحملات الترويجية النشطة الخاصة بالمتجر؛ ولا يعتمد البوت على
حملة قيد المراجعة أو حملة من متجر آخر.
لتفعيل الردود العامة المعتمدة من لوحة الإدارة، طبّق أيضاً
`supabase/migrations/2026_10_04_assistant_reply_rules.sql`؛ تُفحص بعد قواعد
المتجر والردود المبنية على بياناته، وتظهر كلمات كل قاعدة وردها في لوحة الإدارة.

## إحصاءات استخدام المنصة

لتفعيل رسم النشاط حسب الدولة والمدينة والساعة، طبّق
`supabase/migrations/2026_10_04_usage_analytics.sql` في Supabase. يعتمد التوزيع على
الدولة والمدينة اللتين يضيفهما المستخدم إلى ملفه، ولا يجمع GPS أو عنوان IP. يسجل
النظام فترات نشاط مجهولة الهوية مرة واحدة للحساب في الساعة المحلية، ويحذف السجلات
بعد ٩٠ يوماً. تظهر النتائج في لوحة الإدارة بعد بدء الاستخدام.

## إشعارات OneSignal

إشعارات التطبيق الداخلية تقرأ من جدول `public.notifications` الحالي، وتحتاج إضافته إلى Supabase Realtime (وهو مفعّل في قاعدة البيانات الحالية). لا يلزم إنشاء جدول جديد.

اضبط متغيرات البيئة التالية:

```env
NEXT_PUBLIC_ONESIGNAL_APP_ID=
ONESIGNAL_APP_ID=
ONESIGNAL_REST_API_KEY=
ONESIGNAL_WEBHOOK_SECRET=
```

`NEXT_PUBLIC_ONESIGNAL_APP_ID` هو معرّف تطبيق الويب في OneSignal. يمكن ضبط `ONESIGNAL_APP_ID` كنسخة خادمية من المعرّف، وإلا يستخدم المسار القيمة العامة. `ONESIGNAL_REST_API_KEY` و`ONESIGNAL_WEBHOOK_SECRET` أسرار خادمية، ولا تضع بادئة `NEXT_PUBLIC_` عليهما.

من Supabase أنشئ Database Webhook على `public.notifications` لحدث `INSERT`، بعنوان `https://<نطاق-التطبيق>/api/onesignal/notifications`. إذا ضبطت `ONESIGNAL_WEBHOOK_SECRET` فأرسلها في ترويسة `x-onesignal-webhook-secret`. إن لم تضبطها، استخدم ترويسة `Authorization: Bearer <ONESIGNAL_REST_API_KEY>`؛ لا تضع المفتاح داخل عنوان URL. يرسل المسار إشعار OneSignal إلى External ID المطابق لـ `user_id`. يستخدم المتصفح زر «تفعيل إشعارات الجهاز» لطلب إذن Push من المستخدم، وملف `public/OneSignalSDKWorker.js` لخدمة الويب.

يرسل الـWebhook أي صف جديد يُضاف إلى جدول الإشعارات. الدالة الحالية `admin_review_campaign` تنشئ إشعارات قرارات الحملات، وترحيل النشاط يضيف إشعارات التعليقات والمتابعات. تعرض شاشة الإشعارات جميع الأنواع دون تخصيص أو تصفية.

لتنبيهات المحادثات، طبّق `supabase/migrations/2026_10_04_z_message_notifications.sql` بعد ترحيل وجهات الإشعارات. ينشئ الترحيل إشعارًا للمستلم فقط عند إدراج رسالة، ويضيف صورة المرسل ووجهة المحادثة. تأكد من أن جدول `public.notifications` مضاف إلى Supabase Realtime وأن Database Webhook أعلاه ما زال يراقب `INSERT`؛ عندها تظهر الرسالة داخل التطبيق وتصل كـPush للمستخدمين الذين فعّلوا إشعارات الجهاز. أثناء فتح التطبيق يشغّل التنبيه ملف `public/sounds/notification.wav`، أما صوت Push خارج التطبيق فيتحكم به المتصفح/نظام الجهاز ولا يمكن فرض ملف صوت ويب مخصص عليه.

## حماية بيانات الملفات الشخصية

بعد تطبيق الترحيلات السابقة، طبّق
`supabase/migrations/2026_10_08_zzzz_profile_security.sql` على Supabase. يحصر
قراءة جدول `profiles` مباشرةً بصاحب الحساب والمشرف، ويمنع التعديل الذاتي لحقول
الحظر والتعليق والتحقق وتاريخ إنشاء الحساب، بما في ذلك تمريرها عند إنشاء صف جديد.
تستخدم الواجهات العامة العرض `profiles_public` الذي لا يعرض المدينة أو الدولة أو
بيانات الحظر؛ ويكشف رقم WhatsApp فقط للتاجر الذي يعرضه في متجره. لا تُعدّل سياسات
قاعدة البيانات في الإنتاج من ملف `schema.sql`؛ استخدم الترحيل المرتب أعلاه.
لتقييد صور الحسابات والمنتجات العامة إلى JPEG/PNG/WebP وبحجم أقصى ٥ ميجابايت،
طبّق `supabase/migrations/2026_10_08_storage_upload_limits.sql`. يعرض الموقع
الصور من مصدرها ولا يجعل خادم Next.js يجلب روابط الصور التي أدخلها المستخدم.

## غلاف Android بتحديثات الموقع

يستخدم الغلاف Capacitor لعرض أصل الموقع المستضاف مباشرةً، لذا تظهر تحديثات الموقع
لدى المستخدم بعد نشرها وإعادة فتح التطبيق/تحديث الصفحة، ولا يلزم إصدار APK جديد
لتغييرات الواجهة والمحتوى. يلزم اتصال إنترنت، وتغييرات Android أو الإضافات الأصلية
تظل بحاجة إلى بناء وإصدار جديد. لا تضع مفاتيح Supabase أو أي أسرار في إعداد الغلاف.

اضبط `CAPACITOR_SERVER_URL` على أصل HTTPS الإنتاجي (الجذر فقط، بلا مسار) قبل أوامر
Capacitor:

```sh
CAPACITOR_SERVER_URL=https://your-domain.example npm run mobile:add:android
CAPACITOR_SERVER_URL=https://your-domain.example npm run mobile:sync
CAPACITOR_SERVER_URL=https://your-domain.example npm run mobile:open
```

افتح مشروع Android الناتج في Android Studio لبناء APK موقّع؛ غيّر `appId` في
`capacitor.config.ts` إلى معرّف حزمة تملكه قبل النشر. هذا الغلاف ليس تحديثاً
للكود الأصلي عبر الهواء، ولا يحوّل إشعارات OneSignal للويب إلى Push أصلي تلقائياً.
يجب اختبار تسجيل الدخول OAuth، الإشعارات، المكالمات، الروابط الخارجية وسياسات
Google Play على نطاق الإنتاج وجهاز Android حقيقي قبل التوزيع؛ لم يُنتج APK موقّع
من هذا المستودع.
